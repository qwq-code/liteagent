### 共享改动

| 共性问题 | 本次处理 | 边界 |
|---|---|---|
| 跨应用路由已确定，模型仍要重复填写 adapter/action/payload/params | 为固定单路由生成独立工具名，直接接收动作参数；document、target、verify、timeout_ms 放在可选 request_options 中 | 仅序列化投影，不替模型规划或填参数；不把复合业务流程自动变成原子操作 |
| schema 转换误把字段名或 JSON 值当关键字 | 只遍历 schema 节点；保留名为 const/type/x-route 的属性，以及 enum/default/examples 中的字面值 | 原始 schema 保持不变；新服务不支持的 uniqueItems 仍由执行前校验 |
| 缺少新建文档基础操作 | 合入已验证的 document.create，创建并激活一个空白 DOCX/ODT | 内容提取、写入、格式和后续保存分别操作；拒绝覆盖已有目标 |
| 图片导出说明与执行器参数不一致 | 合入 image.export 的 input_path/output_path/loader/quality 契约 | 直接调用和跨应用转发使用同一参数定义，拒绝未知字段 |

### 原子 API 的粒度约定

一个 API 只做一个明确操作，有明确的输入、结果和验证方式，失败后可定位和恢复。
保存、导出、压缩分别操作；同一矩形范围写入或同一属性的有界批量更新可以保留。
不强行拆成逐单元格/逐字符调用。`atomic__` 名称表示一个已发现的固定路由，
不代表其底层具有数据库事务式回滚，也不代表所有旧工具都完成了业务原子化审计。
